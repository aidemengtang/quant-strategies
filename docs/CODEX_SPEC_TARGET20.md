# 任务：A 股策略，目标年化 20%~30%

> 这份文档只写**要求**，不指定策略。选什么品种、什么因子、什么频率，由你决定并论证。
> 但"20%~30%"这个数字必须是真的——下面所有约束都是为了确保它不是靠漏洞凑出来的。

---

## 1. 目标

**A 股市场，扣费后年化 20%~30%，最大回撤不超过 -40%。**

三条解读，请严格遵守：

1. **20%~30% 是目标区间，不是配额**。落在区间内算达成；低于 20% 要如实报告实际值和原因；**高于 35% 默认视为有 bug**，你必须先自证清白（见第 5 节），自证不过就按"未达成"处理。
2. **扣费后**。双边成本按万 5 计，另做千 1 / 千 2 压力测试。滑点必须按你的调仓频率和标的流动性给一个明确假设，写进报告。
3. **A 股**。沪深北交易所上市品种（股票、可转债、ETF 均可，由你选），不许用港股/美股/期货给收益加杠杆。

---

## 2. 铁律（违反即作废）

1. **禁止杠杆**。任意一日 `weights.sum(axis=1) > 1.0 + 1e-9` 即违规。不许融资、不许期权、不许分级、不许"用 120% 仓位模拟"。
2. **禁止未来函数**。`date=t` 的权重只能用 `≤t` 收盘及以前的数据；收益从 `t+1` 起计。`shift(-n)`、`center=True`、全样本 `mean/std/quantile` 标准化，一律算违规。
3. **禁止幸存者偏差**。回测期内的**退市/摘牌标的必须在池子里**，不能只拉今天还在交易的。做不到就必须量化披露偏差方向，并说明这份回测因此高估了多少。
4. **禁止改 `qs/engine.py`**。必须复用现有引擎与成本模型（`run_backtest` / `perf_stats`）。引擎一放宽，所有对比都失效。
5. **禁止改已有策略的默认行为**（`etf_momentum`、`ma_timing`），它们是对照组。
6. **禁止硬编码与日期补丁**。不许把某段收益写成常数；不许 `if date > '2021-03-01': ...` 这类按日历打补丁。所有规则必须是可解释、对全样本一致生效的信号。
7. **禁止样本外调参**。参数只能在 IS 段选定，OOS 只跑一次。跑完再改 = 作废。
8. **禁止营销式报告**。不许只报好年份、不许把成本设 0、不许用"理论收益"代替"可实现收益"。

---

## 3. 你必须先交方案论证，再写代码

不要一上来就写 2000 行。**第一步只写 `docs/proposal_<name>.md`，不超过 2 页**，回答五个问题：

1. **选什么**：品种、池子、因子/信号、调仓频率、持仓数量。
2. **收益从哪来**：为什么这套东西在 A 股能挣 20%+？属于哪一类来源——
   - 风险溢价（承担了什么别人不愿承担的风险？）
   - 流动性溢价（你的容量是不是小到别人进不来？）
   - 结构性错误定价（谁在系统性地卖错？为什么他们不改？）
   - 制度性红利（打新、折价、政策窗口——说明窗口什么时候关）
   - 纯数据挖掘（如果你自己都说不清，就写这一条，然后降预期）
3. **代价是什么**：预期回撤、最长水下时间、容量上限、失效场景。
4. **为什么别人没把它套利掉**：容量？门槛？监管？认知？——这一条答不出来，说明你找到的是噪音。
5. **怎么证伪你自己**：预先写下"如果出现 X 现象，说明这个策略是假的"，然后回测里专门去查 X。

**方案先给我看，通过了再实现。** 方案里出现"我觉得应该能行"这类话，回去重写。

## 4. 验收标准

主口径：单边万 5，区间 **2015-01-01 ~ 2026-11-07**（数据不足的标的从各自首个交易日起算，不许前向填充）。
IS：2015-01 ~ 2020-12（选参）｜OOS：2021-01 ~ 2026-11（只跑一次）。

| 指标 | 及格 | 优秀 |
|---|---:|---:|
| 全样本年化 | ≥ 18.0% | ≥ 25.0% |
| OOS 年化 | ≥ 12.0% | ≥ 18.0% |
| 夏普 | ≥ 0.85 | ≥ 1.20 |
| 最大回撤 | ≥ -40% | ≥ -30% |
| 卡玛 | ≥ 0.50 | ≥ 0.80 |
| 年化双边换手 | ≤ 1200% | ≤ 700% |
| 千 2 成本年化 | ≥ 10% | ≥ 15% |
| 单只平均权重 | ≤ 8% | ≤ 5% |

> 门槛的意思：**20%~30% 是可以带风险的**，所以 MDD 允许 -40%（这是小盘/高换手策略的正常代价）。但"千 2 成本下还要 ≥10%"这条不能松——高收益策略最容易死在成本上。

## 5. 六项验证（缺一项报告不考虑）

| # | 验证 | 合格标准 |
|---|---|---|
| V1 | IS/OOS 切分 | OOS ≥ IS 的 50%，且 ≥ 12% |
| V2 | 参数邻域 | 对主参数做网格（≥ 5×5），报**矩阵**；≥70% 组合年化 > 12%，无悬崖式塌陷 |
| V3 | 成本敏感性 | 万 5 / 千 1 / 千 2，千 2 下 ≥ 10% |
| V4 | 分年度 | 逐年收益表，**每一年的数字都要贴**；单一年份对全样本累计收益的贡献 ≤ 60% |
| V5 | 剔尾 | 剔除最好的 5 个交易日后，年化仍 ≥ 10% |
| V6 | 随机对照 | 同池、同换手、随机抽样跑 200 次，策略落在 **95 分位以上** |

**额外两项（20%+ 策略的专属体检）**：

| # | 验证 | 要求 |
|---|---|---|
| V7 | 容量估算 | 按日均成交额 ×5% 估算策略容量上限（元），写进报告。**如果容量 < 1000 万元，必须明说"个人可跑、机构不可用"** |
| V8 | 收益归因 | 把收益拆成：市场 beta / 风格 beta（小盘、价值、动量等）/ 选股 alpha / 交易摩擦四块。**风格 beta 占比 > 70% 的，不许叫 alpha 策略** |

## 6. 数据环境（我已实测，别重复踩坑）

- akshare 版本 **1.19.1**，不要升级（会再改接口）；
- 全 A 实时快照 `stock_zh_a_spot_em()`：5927 只，**单次耗时约 67 秒**（内部 59 页），别以为卡死；含 `总市值/流通市值`；
- 单只日线 `stock_zh_a_hist(symbol, period="daily", adjust="")` 可用，速度约 **1.4 秒/只**；
- 退市股名单可得：`stock_info_sh_delist()` 161 只、`stock_info_sz_delist()` 212 只（含 `上市日期/终止上市日期`）——**这是防幸存者偏差的关键，务必合并进池子**；
- 可转债：`bond_zh_cov()` 1066 只（含退市）；`bond_zh_hs_cov_daily()` 单只全历史；**`bond_zh_cov_value_analysis` 已坏**，历史转股溢价率拿不到；
- 必须 `export no_proxy='*' NO_PROXY='*'`，否则 requests 会走一个不存在的系统代理直接 SSLEOFError；
- **全 A 逐只拉取 ≈ 2.3 小时**（5900 × 1.4s）。这是可接受的一次性成本，但必须：分批、`--resume` 断点续跑、每批心跳日志、失败清单落盘（不许静默跳过）。
- 若你的机器上有本地全 A 日线库，可以直接读，但**必须保证 `akshare` 路径仍可独立复现**（公开仓库不能让别人跑不起来）。

## 11. 反模式（做了等于没做）

- 用杠杆、用两融、用期权组合"增强"收益 —— 直接违规；
- 只拉在市股票 —— 小盘策略的收益会凭空多出 10 个点；
- 涨跌停照价成交 —— 连板股根本买不进，这是最隐蔽的虚高来源；
- 全市场参数扫 500 组报最好的那组 —— 过拟合；
- 只回测 2013-2015（小票牛市）或 2019-2021（核心资产牛）—— cherry-picking；
- 高频调仓但不算冲击成本 —— 换手 1500% 的策略，成本能吃掉 15 个点；
- 报告只写"年化 28%"，不写"最大回撤 -48%、连亏 3 年"—— 误导。

## 12. 如果你做不到 20%

照实写，但必须完成任务的一半：**给出你能做到的最好数字 + 归因**。

具体要回答三个问题：
1. 在 A 股、扣费、无杠杆、扣冲击成本的条件下，你实测的天花板是多少？
2. 差距出在哪：是信号不够强、成本太高、还是池子太小？
3. 如果要突破，需要放弃哪条约束（加杠杆 / 放松容量 / 接受 -50% 回撤 / 用非公开数据）？代价是什么？

**"做不到"是可接受的交付；"编一个 28%"不是。** 上一个任务的教训已经证明：诚实的 6.8% 比假装的 30% 有用得多。
